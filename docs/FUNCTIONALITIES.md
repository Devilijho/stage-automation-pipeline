# Functionalities Summary (AI & Developer Quick Reference)

Use this reference to understand what each module does without reading the full source code.

## 1. GitHub Indexer (`scripts/sync_github.py`)
- **Purpose**: Builds `config/master_profile.md` from verified GitHub repos and `templates/base_cv.tex`.
- **Attribution safety**: Shallow-clones repos into `.cache/repos/` and runs `git log --author=...` so collaborative repos (`chaski-booking`, `Transcendence`, `cgj-26`) only credit commits and files authored by the user.
- **Flags**: `--skip-clone`, `--include-forks`.

## 2. ATS Tailoring Engine (`scripts/tailor.py`)
- **Purpose**: Generates grounded, 1-page `CV_<Name>_<Company>.pdf` and `LM_<Name>_<Company>.pdf` in `output/<Company>/`, plus `metadata.json`.
- **Grounding**: Only matches keywords from `KNOWN_KEYWORDS` (plus optional `extra_keywords` from `config/projects.json`) that are verified in `config/master_profile.md` or `templates/base_cv.tex`.
- **CV Adaptation**: Updates `CV_TITLE`, `CV_AVAILABILITY` (using `internship.contract_label` from config), role-archetype `CV_ACCROCHE` (`cyber`, `infra`, `web`, `systems`), dynamically includes verified skills from `config/projects.json` (`skills_categories`) with matched keywords **bolded**, and selects the top 3 verified projects from `config/projects.json` with clickable links.
- **Cover Letter Adaptation (`build_lm_tex`)**: French *Vous / Moi / Nous* letter driven entirely by `config/profile.json` + `config/projects.json` (auto-formatted French date, inferred offer city, cleaned prose role titles, archetype-specific *Vous* hook, concrete project accomplishments in *Moi*, and optional `experience_sentence` / `strengths_sentence`).
- **Page Verification**: Compiles via `pdflatex` or `tectonic` and verifies `len(PdfReader.pages) == 1`, auto-trimming project bullets (3 → 2 → 1) if needed.
- **Tracker**: Appends to `data/applications.csv` via `scripts/core/storage.py` (with `fcntl.flock` locking and atomic `os.replace` writes) with columns `Date,Company,Role,URL,Status,CV_Title_Used,Matched_Keywords,CV_PDF,LM_PDF,Notes`, preventing duplicates by both normalized URL and normalized `(Company, Role)` across job boards. Supports `--json` for structured metadata output. `Notes` records the bailout/failure reason on `manual_portal`, `needs_login`, or `expired` offers (cleared on `applied`).

## 2b. Scraped-Offer Cleaning & CV Quality Gate (`scripts/core/offer_text.py` + `tailor.py`)
- **`sanitize_role()`**: Turns listing cards (APEC/Hellowork/Indeed/… "title + F/H + employer + badges + *Il y a N jours*") into a short title: cuts at the gender marker, board name, double-space/ellipsis, strips trailing location/postcode segments and gendered doublets (`Développeur - Développeuse` → `Développeur`), cuts on word boundaries, returns `""` when unrecoverable (also for error pages like *JavaScript is disabled*). Applied in `scrapers/parsers.py` for every source **and** again in `tailor.py` (idempotent), so `--role`/`--url`/`--text` all get clean titles.
- **Employer handling**: `is_generic_company()` flags job boards (`BOARD_NAMES`) and anonymous placeholders. `company_from_listing()` recovers the employer from the card when possible; otherwise the cover letter says *votre entreprise* (no recipient line), and the output folder/files are named `<Board>_<Role>` (+ URL hash on collision) so offers never collide.
- **Fallback role**: if no clean title remains, `tailor.py` uses a generic archetype label (`ARCHETYPE_ROLE_LABELS`: cyber / infra / web / systems) — never raw scraped text.
- **Keyword matching**: single-letter languages (`C`) only count as an uppercase token in a programming context (`C, Python`, `langage C`, `C/C++`); weak aliases (`WEAK_ALIASES`, e.g. *audit*, *shell*, *ip*) need ≥2 occurrences; page chrome after *Offres similaires* is ignored (`focus_job_text`). Project choice breaks ties with the offer archetype (`ARCHETYPE_TERMS`).
- **Relevance gate**: `scrapers/scoring.py::is_irrelevant_offer()` (used by `score_offer`) drops offers with no `preferences.target_roles` signal in the title (or with `avoid_roles` hits and no target term), and offers whose description has <2 target-term stems. Fully driven by `profile.json` preferences.
- **Quality gate** (`cv_quality_issues`, `pdf_fill_ratio`, optional PNG via `pdftoppm`): after compilation `tailor.py` records `quality_warnings`, `cv_fill_ratio`, `company_is_generic`, `cv_preview_png` in `metadata.json` and prints `[!] Quality:` lines (title >78 chars, accroche >520 chars, scraped noise such as *Il y a N jours*/board names/postcodes, page <70% filled). Limits are constants at the top of `tailor.py`.
- **Remake from the UI**: In **4. Applications**, tick offers (or the header checkbox for all filtered rows) and click **Remake selected CV/LM**. `POST /api/applications/remake {urls}` starts `batch_apply.py --remake <urls...>`, which re-fetches each offer (HTTP for LinkedIn/HelloWork/WTTJ, the `.chrome_profile/` browser session for the others) and runs `tailor.py --remake`. The tracker row is updated **in place** (`core/storage.py::refresh_application`: new company/role/title/keywords/PDF paths; `Date` and `Status` kept), and the old output folder is deleted only if renamed and no other row uses it. `applied` offers are never remade (submitted documents stay as sent). Fetch failures (login walls) are logged — run `./stage login` and retry.
- **Audit**: `./stage tailor --audit` scans existing `output/*/metadata.json` + CV `.tex` for the same problems (exit code 2 if any folder is flagged). Regenerate flagged offers from the Applications tab (**Remake selected CV/LM**) or `./stage apply --remake <url...>`.

## 0. Shared Core & Verification (`scripts/core/` & `./stage check`)
- **`scripts/core/config.py`**: Canonical workspace paths, `.env` loader (`load_project_env`), live atomic `profile.json` I/O (`load_profile`, `save_profile`, `load_preferences`), dynamic `parse_internship_dates` / `get_postal_code`, and `custom_rules` matching.
- **`scripts/core/storage.py`**: Single source of truth for `data/applications.csv` (`read_applications`, `check_and_log_application`, `update_application_status`, `bulk_update_application_status`, `detect_source`).
- **`scripts/core/browser_session.py`**: Shared Chrome `SingletonLock` cleanup, Playwright launch config, and atomic `storage_state.json` cookie snapshots.
- **`scripts/core/llm.py` & `scripts/core/logging_utils.py`**: Locked cached LLM fallback (`ask_llm_for_field`, `call_gemini`, `delete_llm_cache_entry`, `replace_llm_cache`) persisting to `data/llm_answer_cache.json`, plus rotating diagnostic logging (`data/stagebot.log`).
- **`./stage check` (`scripts/check_code.py` + `tests/`)**: Runs `py_compile`, AST undefined-name checks, `ruff`, and the offline unit test suite (including `tests/fixtures/` HTML parser & UI server tests).

## 3. Batch Scraper & Ranker (`scripts/batch_apply.py` + `scripts/scrapers/`)
- **Modules**: `scrapers/boards.py` (7 board scrapers), `scrapers/http_client.py` (pooled `requests.Session` + `AsyncBrowserPool`), `scrapers/parsers.py` (JSON-LD & HTML detail extraction), `scrapers/scoring.py` (BUT 2/3 & 3-tier quality ranking).
- **Sources** (`--sources`):
  - LinkedIn public guest API (`fr.linkedin.com/jobs-guest/jobs/api/seeMoreJobPostings/search`, supports `--easy-apply` via `f_AL=true`).
  - HelloWork (`www.hellowork.com/fr-fr/emploi/recherche.html?c=Stage&p=1..5`).
  - Welcome to the Jungle (`wttj`: `www.welcometothejungle.com/fr/jobs?...&refinementList[contract_type][]=internship`).
  - JobTeaser (`jobteaser`: `www.jobteaser.com/fr/job-offers?...&contract_types[]=internship`).
  - Indeed France (`indeed`: `fr.indeed.com/jobs?...&jt=internship`).
  - APEC (`apec`: `www.apec.fr/candidat/recherche-emploi.html/offres-stage.html`).
  - Meteojob (`meteojob`: `www.meteojob.com/jobs?...&contractType=INTERNSHIP`).
- **Cookie Reuse & Concurrency (`AsyncBrowserPool` + `ThreadPoolExecutor`)**: HTTP searches (`linkedin`, `hellowork`, `wttj` Algolia) and HTTP detail fetches (`LinkedIn`, `HelloWork`, and `WTTJ` fast-path) run concurrently using pooled `requests.Session`s. For `jobteaser`, `indeed`, `apec`, `meteojob` (and `wttj` fallback), `batch_apply.py` launches an async 5-tab headless Playwright Chromium pool on `.chrome_profile/` so saved login cookies are reused with smart selector waits and once-per-domain cookie dismissal. Tailoring (`tailor.py`) also runs concurrently across up to 4 workers with `fcntl.flock` CSV locking.
- **Scaling >20 Offers**: `--per-query` auto-scales with `--limit` when omitted, per-source page caps are expanded (including Algolia pagination for `wttj`), and the Web UI (`#q-limit`) supports `5`, `10`, `20`, `30`, `50`, and `100` offers.
- **Scoring (`score_offer`) & Pre-Filter (`is_excluded_final_year_offer`)**: Excludes/penalizes `PFE`, `Fin d'études`, `Fin de cursus`, `Bac+5`, `Master 2` (`-50` or skipped before detail fetch) unless `BUT 2/3` or `Bac+2/3` is explicitly accepted; boosts `BUT 2`, `BUT 3`, `Bac+2`, `Bac+3`, `IUT`, `3 mois`, and Paris/Saclay/Bures-sur-Yvette locations.
- **Modes**: `--scrape-only`, `--auto`, `--retry drafted|manual_portal|pending`, `--skip-external`.

## 4. Async Multi-Tab Browser Assistant (`scripts/apply_browser.py` + `scripts/browser/`)
- **Modules**: `browser/ats_rules.py` (ATS detection, login URLs, submission confirmation), `browser/question_rules.py` (master-profile skill & yes/no matching), `browser/dom_helpers.py` (cookies, Apply redirect following, label extraction), `browser/navigation.py` (Next/Submit discovery, validation errors), `browser/form_filler.py` (inputs, selects, radios, dates, uploads), `browser/runner.py` (auto pool, manual review, login setup).
- **Concurrency**: Uses `playwright.async_api` + `asyncio.Semaphore(5)` (`--tabs 5`) inside 1 persistent Chrome profile (`.chrome_profile/`). `--auto` runs headless (`channel="chromium"`) by default so it never steals OS keyboard/window focus (pass `--headed` to watch it).
- **Automation**:
  - `accept_cookies_if_present`: Dismisses Didomi, OneTrust, Axeptio, Tarteaucitron, and generic French consent modals (including iframes).
  - `click_apply_and_follow_redirect`: Scans main page + iframes, uses `page.expect_popup()` + `context.pages` new-tab fallback, and handles secondary ATS landing buttons (e.g., Lever `/apply`).
  - `fill_matching_fields` + `answer_common_questions`: Scans active modal/page + all `page.frames` (iframes) via `get_form_roots()`; extracts radio options from `<label for>`, wrapping `<label>`, sibling text, `aria-label`, and LinkedIn `.fb-text-selectable__option` via `extract_radio_options()`; matches mandatory GDPR/privacy/contact-consent radios & checkboxes; handles up to `15` multi-step form pages with stuck-step detection (`get_step_signature`) and visible button dumps (`dump_visible_buttons`) on bailout.
  - `inject_files`: Attaches `CV_*.pdf` / `LM_*.pdf` via `<input type="file">` (page + iframes) or `page.expect_file_chooser()`.
  - `uncheck_follow_company`: Unchecks LinkedIn's `#follow-company-checkbox`.
  - `check_submission_confirmed`: Uses per-site confirmation phrases (`SITE_CONFIRMATION_PHRASES` for LinkedIn, HelloWork, WTTJ, JobTeaser, Indeed, APEC, Meteojob) with a generalistic fallback (`CONFIRMATION_PHRASES_EXTERNAL`) for external portals, plus strict URL confirmation tokens (excluding HelloWork `/bounce/createalert` & `origin=responseoffer` redirect URLs), modal closing, and `200/201` POST/PUT submit responses. Manual UI `Skip`/`Mark Applied` actions override status with `force=True`. Separates `needs_login` (e.g. APEC login walls, retryable via `--retry needs_login`) and `expired` (closed/expired Indeed or LinkedIn offers) from `manual_portal`.
- **Session Setup**: `--login` (with optional `--sources ...`) opens LinkedIn, HelloWork, Welcome to the Jungle, JobTeaser, Indeed, APEC, and Meteojob login pages in `.chrome_profile/` so cookies are persisted and reused automatically by both `batch_apply.py` and `apply_browser.py`.

## 5. Spontaneous Local Mailer (`scripts/spontaneous_mail.py`)
- **Purpose**: Queries `recherche-entreprises.api.gouv.fr` for NAF `62.01Z` / `62.02A` companies within 15 km of Bures-sur-Yvette, runs `tailor.py` with `spontaneous://<slug>`, and writes ready-to-open `.eml` drafts + `mailto_link.txt`.

## 6. macOS Web UI (`scripts/ui_server.py` & `ui/`)
- **Frontend Modules (`ui/`)**: Split cleanly into `index.html` (semantic layout), `styles.css` (design tokens & styling), `i18n.js` (`ES | FR | EN` translations), `app.js` (dashboard, tracker, Manual Review, preview, profile, SSE/log polling), and `qa.js` (Q&A rules & LLM cache management), all served directly by `ui_server.py`.
- **Server**: `ThreadingHTTPServer` on `127.0.0.1:8765` with endpoints `GET /api/health`, `GET /api/applications`, `POST /api/applications/status`, `POST /api/manual_action` (`mark_applied`, `skip`, `fill`), `GET /api/profile`, `GET/POST /api/questions`, `GET/POST /api/llm_cache`, `POST /api/run`, `POST /api/applications/remake`, `POST /api/stop`, `GET /api/logs`, `GET /api/report` (with JSON body validation and `CURRENT_PROC` cleanup).
- **UI**: 7-step sidebar (`1. Intro & Guide`, `2. Fetch Offers`, `3. Apply`, `4. Applications`, `5. CV & Letter Preview`, `6. Profile & GitHub`, `7. Q&A & Rules`), `ES | FR | EN` language switcher, live log viewer with actionable `Clean | Raw` toggle, full status sidebar counters (`total`, `applied`, `drafted`, `manual_portal`, `needs_login`, `expired/skipped`), dedicated `Notes / Reason` column (`#th-notes`) in the Applications table, per-platform & 3-tier quality (`high`/`medium`/`low`) filters on Fetch/Apply/Tracker, 1-by-1 Manual Review card with Finder reveal + `View CV & LM` + `Fill Current Page` (re-runs autofill on multi-step external portal pages via `.manual_fill`) + `Mark Applied` + `Skip`, Resume PDF auto-import (`POST /api/import_resume`), `preferences` editor (`POST /api/preferences`), live **Cached LLM Answers** editor/deleter/rule-promoter (`/api/llm_cache`), bulk-skip in Tracker (`POST /api/applications/bulk_status`), and printable IUT University Proof Report (`data/rapport_candidatures.html`).
- **CV Tailoring (`scripts/tailor.py`)**: Per-bullet keyword relevance ranking inside `select_and_format_projects()` and gradual 1-page shrinking (`(3,3,3) -> (3,3,2) -> (3,2,2) -> ...`) with zero LLM calls, parameterized externally via `config/profile.json` and `config/projects.json`.
